# Архитектура Rivus

## Общая схема

```
┌──────────────────────────── React UI (WebView2) ───────────────────────────┐
│ titlebar · tabs · omnibox · panels · settings · internal pages             │
└───────────────▲───────────────────────────────────────────┬────────────────┘
                │ invoke / events                           │ bounds, navigate
┌───────────────┴───────────────────────────────────────────▼────────────────┐
│ Tauri backend (crates/rivus)                                               │
│  AppState · commands · update · proxy                                      │
│                                                                            │
│  ┌─────────────┐   ┌──────────────────┐   ┌──────────────────────────────┐ │
│  │ Rivus Engine│   │ aegis-core       │   │ WebView2 child webview       │ │
│  │ Reader mode │   │ HTTP · filter    │   │ per container, JS + cookies  │ │
│  └─────────────┘   │ cookies · DNS    │   └──────────────┬───────────────┘ │
│                    │ store · vault    │                  │                 │
│                    └────────┬─────────┘                  │ CONNECT         │
│                             │                            ▼                 │
│                    локальный фильтрующий прокси 127.0.0.1:<random>        │
└─────────────────────────────┼──────────────────────────────────────────────┘
                              ▼
                         интернет (TLS end-to-end)
```

## Два движка

### 1. WebView2 — режим совместимости

Основной путь для современных сайтов. Один дочерний webview на контейнер создаётся через `Window::add_child` (Tauri `unstable`). Профиль — отдельный `data_directory`; эфемерные контейнеры — `incognito` и временный каталог.

Плюсы: полный JavaScript, формы, видео, SPA, cookie. Минусы: это Chromium, поэтому fingerprinting-поверхности и поведение cookie определяются WebView2. Rivus добавляет единый UA, DNT/GPC, блокировку хостов и изоляцию профилей.

События `rivus-page` (started/finished) и `rivus-title` поднимаются через `app_handle().emit`, React обновляет адрес, заголовок и спиннер.

### 2. Rivus Engine — свой рендерер

`crates/aegis-engine` — HTML5-парсер (`html5ever`), CSS-каскад с subset селекторов, блочная раскладка и rich text через `cosmic-text`, отрисовка `tiny-skia`. JavaScript не исполняется.

Используется для Reader Mode: страница очищается от навигации, рекламы и форм, пересобирается в читаемый документ и рендерится в PNG. Это одновременно самая сильная приватность (нет JS/canvas) и осознанное ограничение совместимости.

## Поток навигации

1. React разбирает ввод: `rivus://`, http(s), домен или поисковый запрос.
2. URL очищается от tracking-параметров.
3. Для веб-вкладки вызывается `native_navigate`.
4. Бэкенд поднимает/переиспользует webview контейнера, выставляет границы из React и навигирует.
5. `rivus-page` обновляет UI; история пишется локально.

Собственный движок вызывается только при включении чтения или в preview-режиме без Tauri.

## Безопасность

- сайты не получают доступ к Tauri IPC: удалённые origin не входят в capability;
- `open_external` принимает только http/https;
- пароли шифруются ChaCha20-Poly1305, ключ — Windows Credential Manager;
- прокси не расшифровывает TLS и не журналирует запросы;
- обновления проверяются по SHA-256 и запускаются отдельным cmd-скриптом после выхода процесса.

## Ограничения

- WebView2 обязан быть установлен (Windows 10/11 — обычно уже есть);
- собственный движок поддерживает не весь CSS; сложные сайты в Reader Mode выглядят упрощённо;
- контейнеры разделяют один webview на контейнер: переключение вкладок внутри контейнера навигирует поверхность, а не держит несколько процессов;
- блокировка по хосту не видит путь и CNAME-клоакинг.

## Сборка и тесты

```powershell
cargo test -p aegis-core
cargo test -p aegis-engine
cd ui; npm ci; npm run build
cargo build --release -p rivus
```

Релиз собирается GitHub Actions на тег `v*`: `rivus.exe` + `SHA256SUMS` прикрепляются к релизу, автообновление читает их через GitHub API.
